# 2025-12-24_0133 Repo Audit

## Scope
Audit of repository structure, pipeline, storage, docs, and existing reports/todos based on current files.

## Findings
- Core pipeline exists and is wired end-to-end: capture -> transform -> publish -> measure (`pipeline/index.ts`).
- Storage is in transition: filesystem artifacts plus LowDB JSON (`pipeline/db.ts`) and a SQLite backend (`pipeline/storage/backends/sqlite.ts`).
- Docs are extensive (initiation, guides, reference, architecture) and include prior audits in `docs/reports/`.
- RITOps planning and migration analysis are present with a detailed multi-phase roadmap.
- Web UI exists as a separate Vite React app with Tailwind (`web_app/`).
- TODO backlog is detailed and current, with architectural refactors and testing gaps explicitly called out (`TODO.md`).

## Repo Basis (What it is built on)
- Runtime: Node.js, ESM TypeScript (`package.json` type: module).
- Build system: `tsc` to `dist/`, CLI entry `cf` mapped to `dist/bin/cf.js`.
- Package manager: pnpm workspace (`pnpm-workspace.yaml`).
- Pipeline stack: capture scripts in `pipeline/capture/`, transform/publish/measure in `pipeline/`.
- Storage: LowDB JSON file in `data/content-factor.json` plus optional SQLite backend in `data/content-factor.db`.
- UI: React + Vite + Tailwind in `web_app/`.
- Docs site: Astro in `docs/web_portal/`.

## Suggestions
- Prioritize TODO items #1-4 to stabilize pipeline behavior and storage abstraction.
- Add a minimal test harness (Vitest) and start with templates + storage adapters.
- Consolidate storage strategy (filesystem vs JSON DB vs SQLite) and document the single source of truth.
- Add structured logging (pino) to reduce unstructured console output.
- Align docs with actual scripts (update `docs/getting-started.md`).

## Todos (From Backlog)

- Add strict template types and shared content interfaces.
- Introduce config-based paths for pipeline portability.
- Complete storage abstraction and unify link artifact handling.
- Add input validation for interactive capture adapters.
- Establish a testing framework and basic coverage.

## Next Steps

## Additional Report Types (Suggested)
- data-integrity-audit: schema compliance, missing fields, artifact normalization rates.
- pipeline-run-report: per-stage timing, success/failure counts, output sizes.
- dependency-risk-report: outdated packages, known advisories, license drift.
- docs-coverage-report: missing references, stale links, mismatched commands.
- ui-a11y-report: accessibility checks for `web_app/` and docs portal.
- storage-usage-report: storage sizes by backend and data directory growth over time.

## Inspect/Check Types You Can Run and Log
- Todo scan: `pnpm audit:todos` (scans for TODO/FIXME/BUG markers and TODO.md summary).
- Pipeline end-to-end: `pnpm start` (build + capture + transform + publish + measure).
- Stage-specific runs: `pnpm capture:commit`, `pnpm transform`, `pnpm publish-content`, `pnpm measure`.
- Artifact variance inspection: `bin/ritops/artifact/inspect.ts` + `bin/ritops/artifact/inspect-variance.ts` (run after build or with ts-node).
